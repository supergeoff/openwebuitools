# Research Workflow

When the user asks to identify, compare, recommend, or research projects, tools, libraries, products, vendors, or technical options, start with broad discovery through available web search, fetch, crawl, and browser tools, including SearXNG and crawl4ai when available.

After broad discovery, use GitHub MCP for repository-level validation: activity, stars, issues, releases, licenses, source quality, installation shape, and self-hosting evidence.

Do not treat GitHub search alone as sufficient for open-ended discovery unless the user explicitly asks for GitHub-only research.

Prefer primary sources for validation: official docs, repository READMEs, release notes, deployment docs, and maintainer-owned pages.
